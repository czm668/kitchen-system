## 2. MQ-2 分压：`10k + 20k` 是错的

### 2.1 根因

MQ-2 模块需要 5 V 加热，AO 输出最高接近 5 V。ESP32 的 ADC 输入上限是 3.3 V（11 dB 档实际可用到约 3.1 V）。

`02` 文档原来写的 **10k + 20k** 分压比是 `20/(10+20) = 0.667`，5 V → **3.33 V**。这已经超过 3.3 V 供电轨，会打开 ADC 引脚的 ESD 保护二极管：轻则读数被钳位失真，重则长期损伤引脚。而且 3.33 V 也超了 11 dB 档 3.1 V 满量程。

### 2.2 选值计算

判据不是「不超过 3.3 V」，而是「不超过 **线性区上限 2450 mV**」——因为 11 dB 档在 2.45 V 以上明显变缓，而报警判据恰好落在高浓度段。

```
目标：5.0 V × Rb/(Rt+Rb) ≤ 2.45 V  →  Rb/(Rt+Rb) ≤ 0.49
同时：源阻抗 Rt∥Rb < 10 kΩ（ESP32 ADC 建议值，太高采样不稳）
同时：总阻值 10 k~200 kΩ（太小费电，太大易受干扰）
```

E24 系列里满足条件、且源阻抗最低的组合是 **Rt = 10 kΩ，Rb = 9.1 kΩ**：

```
分压比 = 9.1 / 19.1 = 0.4764
5.0 V → 2.382 V          ✅ 在线性区内
源阻抗 = 10k ∥ 9.1k = 4.77 kΩ   ✅ 远低于 10 kΩ
```

代码里可以直接验证：

```python
from kitchen.hal import adc
adc.VoltageDivider(10_000, 9_100).check(5.0)
# (True, '分压后最高 2382 mV，占满量程 77%，在线性区内')

adc.VoltageDivider(10_000, 20_000).check(5.0)
# (False, '分压后 3333 mV 超 11dB 档满量程 3100 mV，会削顶并触发输入保护；必须加大 R_top')
```

`adc.recommend_divider(5.0)` 会按同样判据从 E24 里给出候选（首选 15k+13k → 2321 mV）。

### 2.3 接线

```
MQ-2 模块 AO ──[10 kΩ]──┬── GPIO35（ADC1，仅输入脚）
                        │
                     [9.1 kΩ]
                        │
                       GND
```

- 分压电阻用 **1% 金属膜**，5% 碳膜会引入同量级误差；
- 从 AO 到 ADC 之间穿 100 nF 到地做 RC 低通（与分压并联即可），抑制油烟脉冲和 WiFi 射频耦合；
- 模块 VCC 接 **5 V**（VIN），GND 与 ESP32 共地。若接 3.3 V，加热丝功率不足，读数会整体偏低且漂。

### 2.4 换算代码

关键在于**不能用电压当浓度**。MQ-2 是半导体气敏电阻，要反算 Rs 再对基线归一化：

```python
from kitchen.hal import adc, frontend

gas = frontend.GasChannel(
    adc=adc.AdcChannel(adc.ATTEN_11DB),        # Arduino 默认 11 dB 档
    divider=adc.VoltageDivider(10_000, 9_100),
    v_module=5.0, r_load_ohm=10_000.0,
    alarm_k=4.0,                                # Rs 降到基线 1/4 时 level=1
)
gas.capture_baseline(clean_air_raws)            # 开机前 5 分钟采样，取中位数
level = gas.level(raw)                          # → 0~1，直接对应 gas_level
rate  = gas.crossover_rate(samples)             # → level/分钟，突变率
```

三个设计取舍写在代码注释里，答辩会被问：

1. **基线用中位数不用均值**：油烟、点火、水蒸气都会造成单点尖峰，均值会被拉偏；
2. **归一化到 0~1 而不是报 ppm**：MQ-2 的 ppm 标定受温湿度与老化影响极大，本项目的口径是「只做趋势判定，不做绝对浓度报警」（见 `04_功能规格与联动阈值.md` 功能 #1）；
3. **偏置用样本均值估计**（SCT 那边同理）：偏置网络随温度漂移，硬编码会引入系统误差。

### 2.5 上电验证

```python
# 洁净空气：Rs 应在几十 kΩ 量级，level ≈ 0
# 打火机放气（不对准探头）：level 应快速上升，crossover_rate > 0
```

若 `level` 一直是 0：多半是分压电阻焊反（Rt/Rb 互换），或者模块接的是 3.3 V。

## 3. SCT-013：burden 33 Ω 不够用

### 3.1 根因

两个独立问题：

**① 它是交流信号。** SCT-013 输出的是随工频变化的正负交流电流，直接 `analogRead()` 得到的是围绕偏置波动的瞬时值。取平均恒为偏置电压，取瞬时值是随机相位——**必须算 RMS**。负半周还需要 1.65 V 偏置抬到量程中位，否则直接被削掉一半。

**② 分辨率不够。** 这一条最容易被忽略。SCT-013-000 是 100 A : 50 mA，即 2000:1。排风机电流只有 0.5~2 A，折算到二次侧是 0.25~1 mA。

| burden | 1 A 负载的二次电压 | 11 dB 档 counts | 0.3 A 时 counts |
|---:|---:|---:|---:|
| 33 Ω（常见抄来的值） | 16.5 mV RMS | **22** | **6.5** ← 不可用 |
| 100 Ω（本项目） | 50 mV RMS | **66** | **20** |

11 dB 档 LSB ≈ 0.757 mV。RMS 计算本身会放大噪声（平方后取均值），**低于 10 counts 时读数基本是噪声**；20 counts 勉强可用；60 counts 以上才稳。

`02` 文档原来写「约 33 Ω」，实测账算不过来，改 **100 Ω**。

### 3.2 电路

```
SCT-013 二次侧 ──┬──[100 Ω burden]── GND
                │
                ├──[10 kΩ]──┬── 3.3 V
                │           │
            (节点 A) ───────┤   ← 偏置网络：两个 10 kΩ 分压得 1.65 V
                │           │
                ├──[10 kΩ]──┴── GND
                │
                ├──[10 µF]── GND          ← 偏置滤波，稳定中点
                │
                └── GPIO32（ADC1）
```

要点：
- **burden 100 Ω 用 1% 金属膜**，它的误差直接变成电流测量误差；
- 偏置的两个分压电阻用 **1% 且等值**（10 kΩ + 10 kΩ），不匹配会让中点偏移；
- 10 µF 电解（或 10 µF 陶瓷）必须要，否则 WiFi 射频会把偏置抖起来；
- 输出端再串 **1 kΩ + 100 nF 到地**做低通（截止约 1.6 kHz），滤掉高频开关噪声，不影响 50 Hz。

### 3.3 换算代码

```python
from kitchen.hal import adc, frontend

# 先算账：这套参数在我这个负载下够不够
ch = frontend.AcCurrentChannel(adc.AdcChannel(adc.ATTEN_11DB), burden_ohm=100.0)
d = ch.diagnose(1.8)          # 演示用的排风机电流
print(d.counts_rms, d.ok, d.hint)
# 119 counts / True / '1.8A 时 119 counts，可测上限约 20.5A，余量充足'

# 采样：至少 10 个工频周期（400 点，约 200 ms）
amps = ch.amps(raws[-400:])   # → 直接对应 sct_current
```

`diagnose()` 会主动告诉你不够用：

```python
frontend.AcCurrentChannel(adc.AdcChannel(adc.ATTEN_11DB), burden_ohm=33.0).diagnose(0.3)
# ok=False  '0.3A 仅 15.0 mV ≈ 20 counts ...'  → 按提示改 burden 或换 2.5 dB 档
```

### 3.4 如果要更高精度

| 方案 | 改动 | 效果 | 成本 |
|---|---|---|---|
| **burden 100 Ω（本项目）** | 一颗电阻 | 1.8 A → 119 counts，上限 20.5 A | 0 |
| 换 2.5 dB 档 + 偏置改 0.75 V | 换两个分压电阻 | LSB 减半，counts 翻倍，上限降到 10.6 A | 0 |
| 外置运放（如 SCT-013 专用模块） | 加模块 | 抗干扰好，可调增益 | ≈10 元 |
| 换 ADS1115（16 位 I2C ADC） | 加模块 + 释放 4 个 GPIO | 精度提升一个数量级，顺带解决 MQ-2/火焰的 ADC 精度 | ≈10 元 |

**演示场景（排风机 1~2 A）用第一种就够**，不必加器件。答辩若被问「为什么不用 16 位 ADC」，答案就是这张表：当前配置在 1.8 A 时有 119 counts，量化误差 < 1%，已远优于 ±5% 的判据要求。

### 3.5 上电验证

1. 夹钳不夹线（空载）：`amps` 应 < 0.05 A。
2. 夹台灯/排风机电源线（**只夹一根线，夹两根相零线会抵消**）：隔离测得约 0.1~0.3 A，风机高档 0.5~2 A。
3. 若读数恒为 0：偏置没接（负半周被削）或 burden 开路。
4. 若读数明显偏大一倍：采样点数不是整周期，加大到 400 点。

## 4. 火焰传感器：极性必须现场判

### 4.1 根因

市面上火焰检测模块（KY-026 / YL-38 一类）用 IR 接收管 + 比较器，**AO 输出的极性各厂不统一**：有的模块有火时电压升高，有的降低。硬编码一个方向，换一批模块就全体反了。

而反了的后果不是「读数不准」，是**「有火判成无火」→ 明火离人功能整体失效**（功能 #3 要求「视觉判定无人 + 火焰传感器检测到明火」同时成立才联锁关阀）。这类失效在演示时表现为「点火了但系统没反应」，很难联想到传感器极性。

### 4.2 方案：上电自判 + 迟滞

```python
from kitchen.hal import adc, frontend

flame_a = frontend.FlameChannel(adc.AdcChannel(adc.ATTEN_11DB), name="flame_a")
# 上电自检：无火时读一次、点火时读一次，自动定方向和阈值
flame_a.auto_orient(idle_raw=820, flame_raw=2480)
# → active_high=True, threshold≈1650, hysteresis≈250

state = flame_a.update(raw)        # → 0/1，直接对应 flame_a
```

`auto_orient()` 做三件事：判方向、阈值取两点中值、迟滞取间距的 15%（夹在 30~400 raw 之间）。

**迟滞是必须的**：没有迟滞时，读数在阈值附近抖动会让 0/1 反复翻转，而每一次 0→1 都可能触发「明火离人」去关燃气阀。这种抖动在生产环境一定会发生（火焰本身就在闪）。

### 4.3 接线与替代方案

- AO → **GPIO36 / GPIO39**（仅输入 + ADC1，正合适）；模块 VCC 接 3.3 V 即可（无加热丝）；
- 模块自带的 DO 也可以接到普通 GPIO 做硬阈值备份，但**不要用它替代 AO**：DO 的阈值靠电位器调，无法软改，且没有迟滞。

### 4.4 上电验证

```python
# 三步确认极性没判反：
# 1) 无火：flame.update(idle_raw) → 0
# 2) 打火机在 20 cm 处：flame.update(flame_raw) → 1
# 3) 拿开：flame.update(idle_raw) → 0
```

`describe()` 会打印「有火时读数升高/降低，阈值 ±迟滞」，可直接写进调试日志。

## 5. ADC2 不可用：把约束变成会报错的代码

### 5.1 根因

ESP32 的 ADC2 与 WiFi 射频共用硬件。调用 `WiFi.begin()` 之后，对 ADC2 通道的读数是**随机值，且不报任何错误**。本项目 WiFi 常开，等于 ADC2 永久不可用。

ADC2 的引脚是：GPIO 0/2/4/12/13/14/15/25/26/27。注意这份名单与本项目的 TFT(15/2/4)、继电器(13/14/26)、DFPlayer(25) 全部重叠——**一旦有人把 MQ-2 挪到 13 脚「因为 35 脚要留给别的东西」，系统就会静默失效**。

### 5.2 方案：分配表进代码，改错即报错

`02` 文档 §2.2 那张表在 `pins.py` 里落成了数据，`validate_plan()` 用四条硬约束检查：

```python
from kitchen.hal import pins

issues = pins.validate_plan()
print(len(issues), issues)
# 0 []   ← 当前分配表干净

# 演示：把 MQ-2 挪到 13 脚（ADC2）
broken = [u for u in pins.PIN_PLAN if u.gpio != 35]
broken = [pins.PinUsage(13, "MQ2", "AO", pins.ANALOG_IN) if u.gpio == 13 else u
          for u in broken]
print(pins.validate_plan(broken)[0])
# [ERROR] GPIO13: MQ2 的模拟输入落在 ADC2。WiFi 工作时 ADC2 被射频占用，
#         读数是随机值且不报错；只能用 ADC1（GPIO 32–39）
```

检查项：

| 规则 | 触发条件 | 级别 |
|---|---|---|
| ADC2 上放模拟输入 | `role=analog_in` 且引脚在 ADC2 | error |
| 仅输入脚做输出 | `role=digital_out` 且引脚在 34/35/36/39 | error |
| 复用 flash 脚 | 引脚在 6–11 | error |
| 同一脚两个外设 | 重复 GPIO | error |
| strapping 脚未声明上电电平 | 引脚在 0/2/5/12/15 且 `boot_level=None` | warning |
| 占用 UART0 | 引脚在 1/3 | warning |

**建议接进 CI**：任何改硬件的提交先跑一次 `pytest tests/test_hal_pins.py`，比焊完再查便宜得多。

### 5.3 顺带的好处：文档与代码不会再各说各话

`pins.plan_table()` 会把分配表渲染成 Markdown，可以直接粘回 `02` 文档做一致性核对。`test_extension_plan_references_existing_assignments` 还会验证「腾脚方案假定的引脚确实被那些外设占着」，防止文档过时。

## 6. 修正：继电器触点类型（`02` 文档 §3）

`02` 文档原来写「CH1 用常闭型（继电器）」，按字面接线会得到**相反的效果**：

- 若指「用继电器的 NC 触点」：不吸合时 NC 导通 → **一直给电磁阀供电 → 阀一直开着**。控制器掉电、死机时继电器释放 → NC 导通 → 阀仍然通电开着。这恰恰破坏了失效安全。

正确组合是**常开触点 + 常闭型阀体**，两层「常闭」不能混为一谈：

| 层 | 选型 | 不通电时的状态 |
|---|---|---|
| 继电器触点 | **NO（常开）** | 断开 → 阀体失电 |
| 燃气电磁阀阀体 | **常闭型**（断电关阀） | 关闭 |

于是：

```
继电器不吸合（含掉电 / 死机 / 断线）→ 阀体失电 → 阀关闭   ✅ 失效安全
正常运行                              → 继电器持续吸合 → 阀体得电 → 阀开
需要关阀（联锁）                       → 软件释放继电器   → 阀关闭
```

三路通道统一这个逻辑，「不动作 = 安全侧」：

| 通道 | 触点 | 执行对象 | 不吸合时 | 吸合时 |
|---|---|---|---|---|
| CH1 | NO | 常闭型燃气电磁阀 | **阀关闭** | 阀开 |
| CH2 | NO | 排风扇 | 风机停 | 风机转 |
| CH3 | NO | 工位插座 | 插座断电 | 插座通电 |

⚠️ **继电器模块要选「低电平触发」型**（市面上绝大多数），并在 IN 脚加 **10 kΩ 上拉到 3.3 V**。这样上电瞬间 IN 为高 = 不吸合 = 安全侧；否则 ESP32 上电初期的引脚高阻态可能让模块误吸合，CH1 会在启动瞬间把燃气阀打开一次。

⚠️ CH3 掉电即断电是刻意选择：插座断电属于安全侧（不会漏掉拦截），代价是控制器重启期间工位设备会掉一次电，需要通知操作员。

## 7. GPIO 用满后的扩展

当前分配已占满 28 个可用脚。要加设备时按以下两步腾脚（`pins.extension_plan_summary()` 可打印这段）：

1. **GPIO4（TFT RST）** → 改接 3.3 V 常高（TFT 模块自带 RC 上电复位），腾出作 **I2C SDA**；
2. **GPIO0（LED）** → 移除，或改挂 PCF8575 的 P0（本来就只是状态指示），腾出作 **I2C SCL**。

腾脚后接 PCF8575（16 位 I2C 扩展，约 +8 元），两条线各 4.7 kΩ 上拉到 3.3 V。

⚠️ **GPIO0 是 BOOT 脚**，作 I2C SCL 有残留风险：复位瞬间若从设备正在拉低总线，会误进下载模式。缓解措施三条，必须同时做：
1. 总线 4.7 kΩ 上拉保证复位期为高；
2. 复位期间软件不发起 I2C 事务；
3. PCF8575 的 P 口默认输入态，不会主动拉低总线。

`pins.validate_extension_plan()` 会把这条风险作为 warning 输出，防止后人只看到「腾脚方案」看不到代价。

**更省事的替代**：如果只是要加几个开关量输出，先用 PCF8575 之前可以考虑把声光报警（LED + 蜂鸣器）合并到一个脚的驱动电路上，或直接用 I2C 的 OLED 替代部分 TFT 提示——腾脚永远是最后手段。

## 8. 上电校准流程（接真机第一天做什么）

按顺序做，每步都留下数值，写进调试日志：

| 步骤 | 操作 | 通过判据 |
|---|---|---|
| 1 | 不接任何传感器，串口打印 4 路 ADC 原始值 | 都在 0~4095 且不跳变超过 ±5 |
| 2 | MQ-2 通电预热 **≥ 5 分钟**（加热丝需要），采 300 点建立基线 | Rs 稳定在几十 kΩ，波动 < 5% |
| 3 | 打火机放气（不对准探头） | `gas_level` 上升，`crossover_rate > 0` |
| 4 | SCT-013 空载 | `amps < 0.05` |
| 5 | SCT-013 夹台灯线 | `amps` 与钳形表读数差 < 10% |
| 6 | 火焰传感器无火读数 | `flame.update()` → 0 |
| 7 | 打火机 20 cm 对准 | `flame.update()` → 1，且拿开后回 0 |
| 8 | 两路热电偶室温 | 两路读数差 < 2 °C，且与室温差 < 3 °C |
| 9 | 用万用表量 AD 引脚电压，与 `to_mv()` 结果比对 | 建两点校准（见下） |
| 10 | HX711 空载 → 放 100 g 砝码 | `tare()` 后归零；`calibrate()` 后读数 ±1 g |

**两点校准怎么做**（对应 `adc.TwoPointCalibration`）：给 AD 引脚分别加两个已知电压（如用 10 kΩ 电位器分压 3.3 V，用万用表量准），记下 `raw` 与 `mV`：

```python
cal = adc.TwoPointCalibration(raw_low=412, mv_low=300.0, raw_high=3280, mv_high=2400.0)
ch = adc.AdcChannel(adc.ATTEN_11DB, calibration=cal)
```

这能一并吸收衰减档误差、参考电压偏差、分压电阻实际误差——比查手册曲线省事，也吸收板间差异。
