# 接口与通信契约

> MQTT / REST / WS · 版本 v1.0 · 2026-11-12
> **权威副本是代码**：`02_项目代码/kitchen/scenarios/kitchen.json`（12 遥测 + 9 动作，加载期强校验）。
> 本文是人读版，两者冲突时以 `kitchen.json` 为准。

## 1. MQTT 主题

| 方向 | 主题 | 载荷 |
|---|---|---|
| 上行 | `tele/env` | `{"t": 24.5, "h": 61.0, "ts": ...}` |
| 上行 | `tele/gas` | `{"gas_level": 0.12, "ts": ...}` |
| 上行 | `tele/thermal` | `{"hood_temp": 96.0, "sterilize_temp": 25.0, "ts": ...}` |
| 上行 | `tele/cold` | `{"fridge_temp": 4.2, "freezer_temp": -19.0, "sample_temp": 5.5, "ts": ...}` |
| 上行 | `tele/flame` | `{"flame_a": 1, "flame_b": 0, "ts": ...}` |
| 上行 | `tele/current` | `{"sct_current": 0.85, "ts": ...}` |
| 上行 | `tele/weight` | `{"weight_g": 152.0, "ts": ...}` |
| 下行 | `cmd/<device_id>` | 9 个动作之一 |
| 上行 | `ack/<device_id>` | 命令执行确认 |
| 上行 | `event/<device_id>` | 刷卡、SOP 确认、视觉结果、离线标记 |
| 上行 | `offline/batch/<device_id>` | 断网补传批次 |

**载荷是平铺的**（不带驱动名分组），驱动 `sample()` 直接返回平铺 payload，
展平后落 `sensor_readings`。分组信息由主题承担。

## 2. 遥测指标（12 项，冻结）

| id | 名称 | 单位 | 硬件 | 功能 | 参与判定 |
|---|---|---|---|---:|
| `t` | 后厨环境温度 | °C | DHT11 | #7 | **否**（辅助展示） |
| `h` | 后厨环境湿度 | %RH | DHT11 | #7 | **否** |
| `gas_level` | 燃气浓度（ADC 归一化） | 0~1 | MQ-2 | #1 | 是 |
| `hood_temp` | 排烟罩温度 | °C | MAX6675 CH1 + K 型 | #2 | 是 |
| `sterilize_temp` | 消毒柜温度 | °C | MAX6675 CH2 + K 型 | #15 | 是 |
| `fridge_temp` | 冷藏柜温度 | °C | DS18B20 #1 | #5 | 是 |
| `freezer_temp` | 冷冻柜温度 | °C | DS18B20 #2 | #5 | 是 |
| `sample_temp` | 留样柜温度 | °C | DS18B20 #3 | #6 | 是 |
| `flame_a` / `flame_b` | A/B 工位明火 | bool(0/1) | 火焰传感器 ×2 | #3/#4 | 是（跨源联合） |
| `sct_current` | 排风机运行电流 | A | SCT-013 | #4/#15 | 是（运行态联判） |
| `weight_g` | 称重值 | g | HX711 | #12/#14 | 是（称重门禁） |

**13 类信号 = 12 项遥测 + 1 类 RC522 事件信号**。RC522 不产生数值遥测，走事件主题。

### 命名规范（冻结）

1. 小写蛇形，**不带设备名前缀**；单位写 `unit`，不写进 id。
2. 布尔量用 `0/1` 上报，配 `kind:"bool"` + `true_label`/`false_label`。
3. `aliases` 仅用于模拟器注入兼容，**不进 `sensor_readings`**；同场景内别名不得跨指标重复。
4. 一硬件多路用语义后缀（`_temp` / `_a` / `_b`），**不用通道号**；通道号只用于执行末端。
5. 派生状态（视觉在岗、刷卡身份、互锁状态、离线标记）**不是遥测指标**。

## 3. 动作与执行通道（9 个，冻结）

| 动作 | 驱动 | 通道 | 执行对象 | 目标状态 |
|---|---|---|---|---|
| `gas_valve_close` | `relay3ch` | CH1 | 燃气电磁阀（**常闭型**） | `gas_valve: closed` |
| `gas_valve_open` | `relay3ch` | CH1 | 燃气电磁阀 | `gas_valve: open` |
| `fan_on` | `relay3ch` | CH2 | 排风扇 | `fan: on` |
| `fan_off` | `relay3ch` | CH2 | 排风扇 | `fan: off` |
| `power_cut` | `relay3ch` | CH3 | 工位插座 | `station_power: cut` |
| `power_restore` | `relay3ch` | CH3 | 工位插座 | `station_power: on` |
| `alarm_light_on` | `signal` | 独立 GPIO | 声光报警 LED | `alarm_light: on` |
| `alarm_light_off` | `signal` | 独立 GPIO | 声光报警 LED | `alarm_light: off` |
| `voice_play` | `signal` | 独立 GPIO | DFPlayer 语音 | `voice: played` |

⚠️ **动作名是 `power_restore`，不是 `power_on`。** 写错会被 `manifest.py` 加载期拒绝。

⚠️ **旧场景（明厨亮灶）的 `valve_close` / `valve_open` 禁止带入**：
`channels.py` 硬拦截，且 `manifest.py` 在加载期就报错。旧场景的 `fan_on` 同名但**不是同一执行对象**。

## 4. 事件类型

| 事件 | 来源 | 关键字段 |
|---|---|---|
| `rfid_card` | RC522 | `card_id`、`station_id`、`action`（上灶/出餐/晨检/SOP 确认/复核） |
| `sop_confirm` | TFT | `order_item_id`、`step_id`、`staff_id`、`card_id` |
| `weigh_session` | HX711 + TFT | `order_item_id` 或 `batch_id`、`expected_g`、`actual_g`、`deviation_pct` |
| `vision_event` | YOLOv8 | `label`、`confidence`、`station_id`、`evidence_path`、`model_version` |
| `presence` | YOLOv8 | `station_id`、`occupied`(bool)、`since_ts` |
| `offline_mark` | 端侧 | `device_id`、`online`(bool)、`since_ts` |
| `interlock` | 规则引擎 | `channel`、`latch_key`、`trigger_sources[]`、`state` |

## 5. 断网补传协议

```
端侧断网 → 业务数据 + 本地日志进队列（带单调递增 seq）
        → 恢复后 POST/MQTT 批量上报：{device_id, batch_id, records[{seq, ts, type, payload}]}
        → 服务端按 (device_id, seq) 去重写 offline_batches
        → 时钟校准：用服务端时间 - 端侧 ts 差值修正，同时保留原始 ts
        → 补传完成 → 端侧自动重启视觉判定
```

- `offline_batches(device_id, seq)` **唯一索引**做去重。
- 补传顺序必须按 `seq` 升序，避免状态机回跳。
- 断网期间的动作**全部留痕**，人工动作额外标注 `actor=manual`。

## 6. REST / WS 要点

| 端 | 接口 | 说明 |
|---|---|---|
| 管理端 | `GET /api/orders`、`/api/stations`、`/api/env/points`、`/api/work-orders` | 列表 + 分页 |
| 管理端 | `PATCH /api/env/thresholds/{point_id}` | 改阈值/档位，写 `updated_by` |
| 管理端 | `POST /api/interlock/reset` | **人工复位**，需 `channel` + 双通道确认凭据 |
| 小程序 | `GET /api/orders/{id}`、`POST /api/orders/{id}/urge` | 进度与催菜 |
| 小程序 | `GET /api/trace/{code}` | 扫码溯源 |
| 三端共用 | `WS /ws/events` | 状态推送：订单、互锁、工单、离线标记 |

**并发控制**：订单写操作带 `version`，冲突返回 409，由前端合并重试。

## 7. 契约加载期校验（代码已实现）

`src/kitchen/manifest.py` 在加载 `kitchen.json` 时逐项核对，任何不一致直接抛 `ManifestError`：

1. 驱动类可导入，且类的 `id` / `metrics` / `actions` / `topic` 与 manifest 声明**逐项一致**。
2. 动作名不在旧场景动作集合内（防串路）。
3. 动作名不重复；指标名不重复；别名不跨指标重复。
4. `states` 的键必须是已声明的动作名。
5. 指标名与 12 项冻结口径一致。

这条校验是防「文档改了代码没改」和「抄错动作名」的实际闸门，不是形式主义——
写错一个 `power_on` 会在启动时报错，而不是等到现场才发现继电器不动。
